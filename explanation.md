# Полное объяснение: RPN-калькулятор на M68k

## Что делает программа в целом

Программа реализует **стековый калькулятор в обратной польской записи (RPN)**. Это значит что выражение записывается без скобок, а операторы идут после операндов: вместо `(1 + 2) * 3` пишут `1 2 + 3 *`.

Алгоритм простой: читаем токены слева направо. Число — кладём на стек. Оператор — снимаем два числа со стека, считаем, результат кладём обратно. В конце на стеке должно остаться ровно одно число — это ответ.

Программа читает строку из IO-порта 0x80 (вход), вычисляет результат, пишет в IO-порт 0x84 (выход).

---

## Почему нельзя сократить больше

Прежде чем разбирать код построчно, важно понять ограничения M68k в Wrench, которые делают код именно таким длинным:

1. **Нет арифметики на адресных регистрах.** `add.l 1, A0` — запрещено. Единственный способ двигать указатель — постинкремент `(A0)+` и предекремент `-(A0)`. Поэтому каждое смещение адреса требует именно этих конструкций.

2. **Нет `move.l An, Dn`.** Нельзя скопировать адресный регистр в регистр данных напрямую. Это убирает целый класс оптимизаций.

3. **Нет расширения знака при чтении байта.** `move.b (A0), D0` не обнуляет старшие 3 байта D0 — там может быть мусор. Поэтому каждый раз нужно делать `clr.l D1 / move.b D0, D1 / move.l D1, D0` — три инструкции вместо одной.

4. **Нет `movsb`-подобных инструкций, нет умножения с двумя регистрами результата.** `mul.l` перезаписывает D0, поэтому перед делением нужно вручную сохранять операнды в D2/D3.

5. **Стек процессора (A7) нужно инициализировать вручную** — Wrench не делает этого автоматически.

6. **Процедуры требуют полного соглашения о регистрах.** Так как нет автоматического сохранения регистров (нет push/pop в x86-стиле для data-регистров), все регистры используются по фиксированному соглашению через всю программу — нельзя просто вызвать процедуру не зная что она делает с D0..D6.

## Структура программы

```
.data              ← константы и буферы в памяти
.text
  _start           ← точка входа: инициализация, вызов процедур
  token_loop       ← главный цикл: читаем токены
  tl_dispatch      ← определяем тип токена
  chk_minus        ← '-' это оператор или знак числа?
  op_add/sub/mul/div  ← четыре оператора
  tl_end           ← проверка и вывод результата
  return_invalid   ← выход с -1
  return_overflow  ← выход с 0xCCCCCCCC
  --- процедуры (после halt) ---
  read_line        ← читаем строку из IO
  check_not_empty  ← проверяем что строка не пустая
  pop_two          ← снимаем два числа со стека
  push_val         ← кладём число на стек
  parse_number     ← парсим целое число из строки
```

Процедуры стоят **после** точек `halt` — это не случайно. Если бы они шли до `_start`, CPU выполнил бы их при старте вместо основной программы (Wrench начинает с первой инструкции в `.text`).

## Построчное объяснение

### Секция `.data` (строки 22–27)

```asm
    .data
```
Директива: всё что ниже — данные, не код. Размещается в памяти отдельно от инструкций.

```asm
input_addr:   .word 0x80
```
В памяти по метке `input_addr` лежит 32-битное слово со значением `0x80`. Это **не** сам IO-порт — это адрес порта, сохранённый в памяти. Нужен потому что `movea.l` на M68k умеет загружать адрес из метки, но не из произвольной константы напрямую в нужном нам двухшаговом виде.

```asm
output_addr:  .word 0x84
```
Аналогично для выходного IO-порта 0x84.

```asm
OVERFLOW_VAL: .word 0xCCCCCCCC
```
Константа переполнения. Хранится в памяти потому что `move.l 0xCCCCCCCC, (A2)` — запись большой константы напрямую в IO — не поддерживается в один шаг. Нужен промежуточный регистр, а для этого нужно сначала откуда-то загрузить значение.

```asm
input_buf:    .byte 0,0,0,...   (65 байт)
```
Буфер для входной строки: 64 байта данных + 1 байт нуль-терминатора. Инициализирован нулями явно — Wrench не поддерживает директиву `.space N` для выделения блока.

```asm
calc_stack:   .byte 0,0,0,...   (256 байт)
```
Память для стека калькулятора. 256 байт = 64 числа по 4 байта. Стек растёт вверх: A4 начинает с начала этой области и движется к концу при push. Инициализация нулями обязательна по той же причине.

---

### Секция `.text` (строки 29–30)

```asm
    .text
    .org 0x200
```
`.text` — секция кода. `.org 0x200` — начать размещение кода с адреса 0x200 (512). Это оставляет пространство 0x000–0x1FF для данных и системных нужд, не перекрывая их кодом.

---

### `_start` — точка входа (строки 35–49)

```asm
_start:
    movea.l  input_addr, A1
```
`movea.l` — загрузка длинного слова в **адресный** регистр. `input_addr` — это метка, то есть адрес ячейки в памяти. После этой команды A1 содержит **адрес** в памяти, где лежит слово 0x80. Режим адресации: **абсолютный** (по имени метки).

```asm
    movea.l  (A1), A1
```
Теперь читаем то, что лежит **по адресу A1** — то есть считываем само значение 0x80. Режим адресации: **косвенный через регистр**. После этого A1 = 0x80 — это уже настоящий адрес IO-входа. Двухшаговая загрузка нужна потому что в M68k Wrench нет способа загрузить произвольную 32-битную константу напрямую в адресный регистр без промежуточной ячейки памяти.

```asm
    movea.l  output_addr, A2
    movea.l  (A2), A2
```
То же самое для A2 = 0x84 (IO-выход). Два шага по той же причине.

```asm
    movea.l  0x0FFC, A7
```
Инициализация **системного стека**. A7 — это регистр стека процессора (SP). Когда выполняется `jsr`, процессор автоматически делает `-(A7)` и записывает туда адрес возврата. Потом `rts` читает адрес обратно через `(A7)+`. Если A7 не инициализировать, он указывает в случайное место памяти и `jsr` испортит данные или код. Значение 0x0FFC = 0x1000 - 4 — это конец доступной памяти (size 0x1000) минус 4 байта под первый адрес возврата. Стек растёт **вниз**.

```asm
    jsr      read_line
```
**Jump to Subroutine** — вызов процедуры. Процессор: 1) записывает адрес следующей инструкции на стек (A7 -= 4, пишет адрес), 2) переходит на метку `read_line`. Это и есть **использование стека для процедур**.

```asm
    jsr      check_not_empty
```
Второй вызов. К этому моменту `read_line` уже вернулась через `rts`, A0 указывает на начало `input_buf`.

```asm
    movea.l  calc_stack, A4
```
A4 = адрес начала буфера `calc_stack`. Это база нашего стека калькулятора. Режим адресации: **абсолютный**.

```asm
    clr.l    D4
```
D4 = 0. Счётчик глубины стека. Нужен отдельно потому что у нас нет способа вычислить глубину из разности A4 и базы — нельзя сделать `sub Ax, Dx` на M68k в Wrench.

---

### `token_loop` — главный цикл (строки 55–60)

```asm
token_loop:
    move.b   (A0), D0
```
**Peek** — читаем текущий байт **без сдвига** A0. Режим адресации: **косвенный через регистр** без инкремента. A0 остаётся на месте.

```asm
    cmp.b    0x20, D0
    bne      tl_dispatch
```
Сравниваем с пробелом (0x20). Если не пробел — идём разбирать токен. `cmp.b` — сравнение только младшего байта, что правильно: мы читали байт.

```asm
    move.b   (A0)+, D0
    jmp      token_loop
```
Это пробел — **потребляем** его: `(A0)+` читает байт и сдвигает A0 вперёд на 1. Возвращаемся в начало цикла. Двойное чтение (сначала peek, потом consume) нужно потому что M68k не имеет инструкции "посмотреть и решить что делать с одним шагом" — peek и consume это разные режимы адресации.

---

### `tl_dispatch` — определение типа токена (строки 62–81)

```asm
tl_dispatch:
    cmp.b    0, D0
    beq      tl_end
```
D0 содержит байт из peek. Если это нуль — строка закончилась, идём к завершению.

```asm
    move.b   (A0)+, D0
```
**Consume** первый байт токена — теперь A0 уже указывает на следующий символ после него. С этого момента D0 хранит тип токена (оператор или первая цифра числа).

```asm
    cmp.b    0x2B, D0   beq op_add    ; '+' = ASCII 43
    cmp.b    0x2D, D0   beq chk_minus ; '-' = ASCII 45
    cmp.b    0x2A, D0   beq op_mul    ; '*' = ASCII 42
    cmp.b    0x2F, D0   beq op_div    ; '/' = ASCII 47
```
Последовательная проверка на каждый оператор. В M68k нет `switch` — только цепочка `cmp + beq`. Порядок важен: '-' проверяется отдельно от других, потому что может быть и оператором, и знаком числа.

```asm
    cmp.b    0x30, D0   blt return_invalid   ; < '0'
    cmp.b    0x39, D0   bgt return_invalid   ; > '9'
```
Если символ не попал ни в один оператор и не является цифрой (диапазон '0'=0x30 .. '9'=0x39) — выражение невалидно.

```asm
    clr.l    D5
    jsr      parse_number
    jmp      token_loop
```
Это цифра. D5 = 0 (знак положительный). Вызываем процедуру парсинга числа. После возврата — следующий токен.

---

### `chk_minus` — неоднозначность '-' (строки 83–92)

```asm
chk_minus:
    move.b   (A0), D1
```
A0 уже прошёл мимо '-'. Делаем **peek следующего** символа в D1 — не потребляем его.

```asm
    cmp.b    0x30, D1
    blt      op_sub
    cmp.b    0x39, D1
    bgt      op_sub
```
Если следующий символ — не цифра, то '-' это оператор вычитания. Прыгаем в `op_sub`. Если цифра — это отрицательное число.

```asm
    move.l   1, D5
    move.b   (A0)+, D0
    jsr      parse_number
    jmp      token_loop
```
D5 = 1 (отрицательный знак). Потребляем первую цифру в D0 (со сдвигом A0). Вызываем парсер — он видит D5=1 и в конце сделает `neg.l D0`.

---

### Операторы `op_add`, `op_sub`, `op_mul` (строки 97–116)

Все три устроены одинаково, например:

```asm
op_add:
    jsr      pop_two
```
Вызов процедуры `pop_two`. После возврата: D0 = a (нижний операнд), D1 = b (верхний), D4 уменьшен на 2.

```asm
    add.l    D1, D0
```
a + b. Результат в D0. Режим адресации: **регистр-регистр**.

```asm
    bvs      return_overflow
```
**Branch if oVerflow Set** — если при сложении произошло переполнение 32-битного знакового числа (флаг V в регистре статуса), уходим в обработчик переполнения. Это единственный способ детектировать overflow на M68k — через флаг после арифметической операции.

```asm
    jsr      push_val
    jmp      token_loop
```
Кладём результат на стек, переходим к следующему токену. Нельзя сделать `jsr push_val / jsr token_loop` потому что `token_loop` — это не процедура, это главный цикл программы, он не должен возвращаться.

---

### `op_div` — деление с floor (строки 118–137)

Деление особое, потому что Python использует **floor division** (округление к минус бесконечности), а M68k `div.l` делает **truncated division** (усечение к нулю). Для положительных чисел разницы нет. Для отрицательных: 7 / (-2) при truncation = -3, при floor = -4.

```asm
op_div:
    jsr      pop_two
    cmp.l    0, D1
    beq      return_invalid
```
Деление на ноль → -1. Проверяем **до** `div.l` потому что деление на ноль — исключение процессора, которое Wrench не умеет обрабатывать.

```asm
    move.l   D0, D2
    move.l   D1, D3
```
Сохраняем a и b в D2/D3. Они понадобятся для коррекции. Нельзя не сохранять — `div.l` уничтожит D0, а `mul.l` ниже уничтожит D6.

```asm
    div.l    D1, D0
```
D0 = a / b, усечённое к нулю. На настоящем M68k `div.l` пишет частное в D0 и остаток в другой регистр, но в Wrench — только частное.

```asm
    move.l   D0, D6
    mul.l    D3, D6
```
D6 = частное × b. Это нужно чтобы вычислить остаток вручную, поскольку Wrench не даёт нам остаток от `div.l` напрямую.

```asm
    sub.l    D6, D2
```
D2 = a - (q × b) = **остаток**. По свойству целочисленного деления: a = q × b + r, значит r = a - q × b.

```asm
    cmp.l    0, D2
    beq      od_done
```
Если остаток равен нулю — деление точное, коррекция не нужна.

```asm
    move.l   D2, D5
    xor.l    D3, D5
    bpl      od_done
```
Смотрим на знаки остатка (D2) и делителя (D3). `xor.l` на двух числах: если их знаки (старшие биты) одинаковы — старший бит результата XOR = 0, флаг N не установлен. Если знаки разные — старший бит = 1, флаг N установлен. `bpl` (branch if plus, то есть N=0) — прыгаем если знаки **одинаковые** (коррекция не нужна).

```asm
    sub.l    1, D0
```
Знаки разные → truncation дал неправильный ответ → floor = truncation - 1.

```asm
od_done:
    bvs      return_overflow
```
Overflow при делении возможен только в одном случае: INT_MIN / -1 (результат не влезает в 32 бит). Флаг V будет установлен.

---

### `tl_end` — завершение (строки 140–145)

```asm
tl_end:
    cmp.l    1, D4
    bne      return_invalid
```
После разбора всей строки на стеке калькулятора должно быть ровно 1 число. Если больше — в выражении было лишних чисел. Если 0 — выражение было пустым (но это поймала `check_not_empty`). В любом отклонении от 1 → ошибка.

```asm
    move.l   -(A4), D0
```
Pop результата. `-(A4)` — предекремент: A4 -= 4, потом читаем. Это стандартная операция снятия значения со стека растущего вверх.

```asm
    move.l   D0, (A2)
```
Запись результата в IO-порт 0x84. Режим адресации: **косвенный через регистр** (A2 содержит адрес 0x84).

```asm
    halt
```
Остановка симулятора. Всё что после — не выполняется. Именно поэтому процедуры можно безопасно разместить ниже.

---

### `return_invalid` и `return_overflow` (строки 147–155)

```asm
return_invalid:
    move.l   -1, (A2)
    halt
```
Ошибочный результат: недостаточно операндов, деление на ноль, невалидный символ, пустая строка. Записываем -1 напрямую. Режим адресации: **непосредственный операнд** (-1) → **косвенный** (A2).

```asm
return_overflow:
    movea.l  OVERFLOW_VAL, A5
    move.l   (A5), D0
    move.l   D0, (A2)
    halt
```
Три шага вместо одного — вынужденная мера. Нельзя сделать `move.l 0xCCCCCCCC, (A2)` напрямую потому что запись 32-битной константы напрямую в ячейку памяти (не регистр) не поддерживается. Нужен промежуточный регистр. A5 загружает адрес метки, потом читаем по адресу (косвенная адресация), потом пишем в IO.

---

### `read_line` — процедура чтения (строки 162–177)

```asm
read_line:
    movea.l  input_buf, A0
```
A0 = адрес начала буфера. Абсолютная адресация по имени метки. Каждый вызов начинает с начала буфера — процедура не имеет состояния.

```asm
    move.l   64, D1
```
D1 = счётчик оставшихся байт. Максимум 64 — размер буфера без нуль-терминатора.

```asm
rl_loop:
    cmp.l    0, D1
    beq      return_overflow
```
Если счётчик дошёл до нуля, а '\n' так и не встретился — строка длиннее 64 символов. По условию задачи `read_line(input, 0x40)` возвращает `None` при переполнении, что соответствует `0xCCCCCCCC`. Прямой прыжок в `return_overflow` — без `rts`, процедура не возвращается в caller, а сразу выводит ответ и останавливается. Это допустимо потому что переполнение — терминальное состояние.

```asm
    move.l   (A1), D0
```
Читаем байт из IO-порта. A1 = 0x80. Режим: **косвенный через регистр**. Результат — 32-битное слово, но нас интересует только младший байт (символ ASCII).

```asm
    cmp.l    0x0A, D0
    beq      rl_done
```
0x0A = символ '\n' (перевод строки). Сравниваем с полным словом потому что IO вернул 32-битное значение.

```asm
    move.b   D0, (A0)+
```
Пишем **только байт** (`.b`) в буфер и двигаем A0 вперёд. Режим: **косвенный с постинкрементом**. Постинкремент для `.b` сдвигает указатель на 1 байт. Именно `.b` — нас интересует только символ, не всё 32-битное слово IO.

```asm
    sub.l    1, D1
    jmp      rl_loop
```
Уменьшаем счётчик, повторяем.

```asm
rl_done:
    move.b   0, (A0)
```
Нуль-терминатор: записываем 0 по текущему A0 **без** инкремента. После этого строка в буфере — корректная C-строка.

```asm
    movea.l  input_buf, A0
    rts
```
Сбрасываем A0 на начало буфера — чтобы следующая процедура (`check_not_empty`) начинала с начала. `rts` — **Return from Subroutine**: читает адрес возврата со стека (A7 += 4), прыгает туда. Управление возвращается в `_start` на строку после `jsr read_line`.

---

### `check_not_empty` — проверка непустоты (строки 184–192)

```asm
check_not_empty:
cne_loop:
    move.b   (A0)+, D0
```
Читаем байт с постинкрементом. Здесь мы **потребляем** байты — ищем первый не-пробел.

```asm
    cmp.b    0, D0
    beq      return_invalid
```
Если встретили нуль (конец строки) раньше чем непробельный символ — строка пустая или состоит только из пробелов. По условию задачи → -1. Прямой прыжок, без `rts`.

```asm
    cmp.b    0x20, D0
    beq      cne_loop
```
Пробел — пропускаем, продолжаем.

```asm
    movea.l  input_buf, A0
    rts
```
Нашли не-пробельный символ. Сбрасываем A0 на начало буфера. Почему не оставляем A0 на найденном символе? Потому что главный цикл `token_loop` сам умеет пропускать пробелы — проще сбросить в начало и не нарушать инвариант. `rts` — возврат в `_start`.

---

### `pop_two` — снятие двух операндов (строки 200–207)

```asm
pop_two:
    cmp.l    2, D4
    blt      return_invalid
```
Проверка глубины. D4 < 2 означает что на стеке меньше двух чисел — невалидное выражение (оператор без операндов). Прыжок напрямую в `return_invalid` без `rts` — терминальная ошибка.

```asm
    move.l   -(A4), D1
    sub.l    1, D4
```
**Предекремент**: сначала A4 -= 4, потом читаем. Это операция POP для стека растущего вверх. D1 = b (тот операнд что был положен последним — "верхний").

```asm
    move.l   -(A4), D0
    sub.l    1, D4
    rts
```
Аналогично для a. D0 = a (был положен раньше — "нижний"). В RPN `a b оператор` означает `a оп b`, поэтому важно не перепутать порядок. Если написать `a 3 /` — это `a / 3`, не `3 / a`.

---

### `push_val` — помещение на стек (строки 213–216)

```asm
push_val:
    move.l   D0, (A4)+
    add.l    1, D4
    rts
```
**Постинкремент** для `.l` сдвигает A4 на 4 байта — размер long word. Пишем D0, потом A4 уходит вперёд. D4++. Три строки — минимум для push с учётом счётчика. Сделать короче нельзя.

---

### `parse_number` — парсинг числа (строки 223–256)

Это самая длинная процедура и она **не может быть короче** из-за ограничений M68k.

```asm
parse_number:
    sub.b    0x30, D0
```
Переводим ASCII-код цифры в её числовое значение: '0'=0x30, '1'=0x31, ..., '9'=0x39. Вычитаем 0x30 — получаем 0..9. Операция `.b` — только на байте D0.

```asm
    clr.l    D1
    move.b   D0, D1
    move.l   D1, D0
```
**Расширение байта до 32 бит без знака.** Нельзя просто использовать D0 как есть — его старшие 3 байта могут содержать мусор от предыдущих операций. Нет инструкции `movzx` как в x86. Поэтому: очищаем D1 полностью, копируем байт туда, копируем 32-битный D1 обратно в D0.

```asm
pn_loop:
    move.b   (A0), D1
```
Peek следующего байта. A0 не меняется.

```asm
    cmp.b    0x30, D1
    blt      pn_done
    cmp.b    0x39, D1
    bgt      pn_done
```
Две проверки — диапазон цифр. Нельзя сделать одной инструкцией — M68k не имеет `cmp in range`.

```asm
    move.b   (A0)+, D1
```
Подтверждаем потребление байта — теперь с инкрементом A0.

```asm
    mul.l    10, D0
    bvs      return_overflow
```
`D0 = D0 × 10`. Алгоритм накопления: для числа "123" делаем `((0×10+1)×10+2)×10+3`. `bvs` ловит переполнение при умножении.

```asm
    sub.b    0x30, D1
    clr.l    D2
    move.b   D1, D2
    add.l    D2, D0
    bvs      return_overflow
    jmp      pn_loop
```
Снова расширяем цифру через D2 (та же проблема с мусором в старших байтах). Добавляем к накопленному. Проверяем переполнение при сложении.

```asm
pn_done:
    move.b   (A0), D1
    cmp.b    0, D1
    beq      pn_sign
    cmp.b    0x20, D1
    beq      pn_sign
    jmp      return_invalid
```
После последней цифры должен стоять пробел или конец строки. Если что-то другое — невалидный токен (например "12abc").

```asm
pn_sign:
    cmp.l    1, D5
    bne      pn_push
    neg.l    D0
```
Если D5=1 (отрицательное число) — инвертируем знак. `neg.l` заменяет D0 на -D0.

```asm
pn_push:
    jsr      push_val
    rts
```
**Вложенный вызов**: `parse_number` сама вызывает `push_val` через `jsr`. В этот момент на системном стеке A7 лежат **два** адреса возврата — тот кто вызвал `parse_number`, и тот что нужен для возврата из `push_val`. Это и есть вложенные процедуры: стек автоматически отслеживает глубину вызовов. `rts` в конце возвращает управление туда кто вызвал `parse_number` (в `token_loop`).

---

## Итог: что реализовано и почему именно так

### Два стека одновременно

Программа использует **два стека параллельно**:

- **Системный стек (A7)** — для адресов возврата из процедур (`jsr`/`rts`). Растёт вниз от 0x0FFC.
- **Стек калькулятора (A4)** — для чисел RPN-выражения. Растёт вверх от `calc_stack`.

Они растут навстречу друг другу в одном адресном пространстве, что является классической схемой для встроенных систем.

### Режимы адресации задействованные в программе

| Режим | Пример | Применение |
|---|---|---|
| Абсолютный | `movea.l input_buf, A0` | Загрузка адресов меток |
| Косвенный | `movea.l (A1), A1` | Разыменование указателей |
| Косвенный с постинкрементом | `move.b (A0)+, D0` | Чтение потока байт |
| Косвенный с предекрементом | `move.l -(A4), D0` | Pop со стека |
| Непосредственный | `move.l -1, (A2)` | Константы в операциях |
| Регистр-регистр | `add.l D1, D0` | Арифметика |

### Вложенность процедур

```
_start
  └─ jsr read_line          (глубина A7: 1)
       └─ rts               (глубина A7: 0)
  └─ jsr check_not_empty    (глубина A7: 1)
       └─ rts               (глубина A7: 0)
  └─ token_loop
       └─ jsr parse_number  (глубина A7: 1)
            └─ jsr push_val (глубина A7: 2)  ← вложенность!
                 └─ rts     (глубина A7: 1)
            └─ rts          (глубина A7: 0)
       └─ jsr pop_two       (глубина A7: 1)
            └─ rts          (глубина A7: 0)
       └─ jsr push_val      (глубина A7: 1)
            └─ rts          (глубина A7: 0)
```
